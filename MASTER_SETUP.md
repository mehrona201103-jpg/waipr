# WAIP SHOP MASTER — контрольный модуль

В архив добавлен `master_manager.py`: центральная база дочерних магазинов, защищённое хранение токенов через Fernet, журнал продаж, расчёт 20% от выручки в Telegram Stars за завершённую неделю, фиксация оплаты и блокировка просроченных магазинов.

## Правила
- RUB-каталог и игровой донат не участвуют в комиссии и остаются в исходном магазине без изменений.
- Комиссия: `ceil(успешные продажи в XTR за неделю * 0.20)`.
- Возвраты/отмены не должны отправляться в `record_sale`; дубли заказов отсекаются уникальным `external_order_id`.
- После трёх дней с выставления счёта неоплаченный дочерний магазин получает статус `suspended`.
- После подтверждения XTR-платежа MASTER вызывает `mark_commission_paid(payload)` и `reactivate_if_paid(tenant_id)`.

## Установка ключа шифрования
```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```
Сохраните результат в секретной переменной `WAIP_MASTER_FERNET_KEY`. Не публикуйте её.

## Важное ограничение текущей сборки
Это подготовленный управляющий модуль и схема данных, но не полностью подключённая мультибот-платформа: исходный WAIP SHOP V2/V3 построен вокруг одного глобального экземпляра `Bot`, одной конфигурации игрового MySQL и одного WebApp. Для фактического клонирования всех обработчиков в независимые дочерние процессы необходимо отдельно завершить маршрутизацию каждого магазина (отдельный DB namespace, WebApp tenant routing, process supervisor и отправку `record_sale` при каждом успешном платеже). До этого не вводите токены дочерних ботов и не считайте, что их обслуживание уже запущено.

Также Telegram Stars не переводятся автоматически с баланса одного бота на другой. В этой реализации дочерний администратор должен оплатить XTR-инвойс, выставленный MASTER-ботом; только успешный `successful_payment` MASTER подтверждает комиссию.

# WAIP SHOP — магазин + создание своих ботов (V13)

Один код: основной бот (мастер) и дочерние магазины. Дочерний магазин — тот же код,
который мастер запускает отдельным процессом со своими настройками.

## Что исправлено по прошлому аудиту
- Вход в аккаунт теперь требует **игровой пароль** (сверка с хешем в MySQL). Раньше любой мог привязать чужой ник и сбросить его пароль.
- Смена аккаунта тоже требует пароль и подписку. Обхода подписки через `switch` больше нет.
- Пароль MySQL нельзя задать через чат (`/db` удалён). Доступы — только в переменных окружения.
- Генерация паролей через криптостойкий генератор (`secrets`).
- Удалён CryptoBot. Все цены и тексты — только в **Telegram Stars**, USD нигде не показывается.
- Порт берётся из `PORT` (Render), а не захардкожен.
- Личный username и ссылка-заглушка на APK убраны из кода (теперь переменные окружения).

## Как работает создание бота
1. В WebApp: Профиль → **Создать своего бота**.
2. Пользователь принимает условия (комиссия 20% от выручки раз в неделю).
3. Заполняет: название (станет именем бота), цвет, логотип (необязательно), токен бота, Telegram ID администратора, MySQL HOST / PORT / LOGIN / PASSWORD / имя базы, хеш пароля.
4. **Проверить данные**: мастер вызывает `getMe` для токена и подключается к MySQL (`SELECT 1`, наличие таблицы `accounts` и колонок).
5. Если всё верно появляется **Создать бота**. Идёт процесс с кругом 0→100% и логами.
6. Мастер запускает процесс магазина, ждёт `/health` и выдаёт ссылку на бота.

Магазин открывается по адресу `https://<сервис>/t/<id>/webapp/`. Мастер проксирует запросы в процесс магазина.

## Комиссия
- Раз в неделю (пн–вс, UTC) мастер считает выручку каждого магазина в Stars.
- Комиссия = 20% от выручки, округление вверх. **Выручки не было — счёта нет.**
- Счёт (Telegram Stars invoice) приходит администратору магазина от основного бота.
- Не оплачено за 3 дня — магазин приостанавливается, после оплаты запускается сам.
- Дочерний магазин сообщает мастеру о каждой выданной покупке (`/internal/sale`, по секрету магазина).

## Переменные окружения (Render → Environment)
Мастер:
- `BOT_TOKEN`, `OWNER_ID`, `WEBAPP_URL` (вида `https://сервис.onrender.com/webapp/`)
- `CHANNEL_USERNAME` или `CHANNEL_ID`, `CHANNEL_URL` (для обязательной подписки)
- `GAME_DB_HOST`, `GAME_DB_PORT`, `GAME_DB_USER`, `GAME_DB_PASSWORD`, `GAME_DB_NAME`
- `PASSWORD_HASH` — `md5`, `sha1`, `sha256`, `double_md5`, `whirlpool` или `plain`
- **`WAIP_MASTER_FERNET_KEY`** — ключ шифрования токенов и паролей. Создать:
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
  **Потеряешь ключ — не расшифруешь токены созданных ботов.** Храни копию отдельно.
- **`TENANTS_DIR`** — папка на постоянном диске, например `/var/data/tenants`
- `MONEY_PER_STAR` (по умолчанию 2000), `MONEY_MIN_UNITS` (100000)
- `STARS_GIFT_USERNAME`, `APK_DOWNLOAD_URL` — необязательно

Дочерние магазины получают свои переменные автоматически. Мастерские переменные (включая `WAIP_MASTER_FERNET_KEY`) им **не передаются**.

## Установка и запуск
```bash
pip install -r requirements.txt
python main.py
```
Тесты (без Telegram и MySQL, на заглушках):
```bash
python -m unittest tests/test_suite.py -v
```

## Сохранение данных на бесплатном плане
Заказы, список созданных ботов и логотипы копируются в приватный Telegram-канал (`BACKUP_CHAT_ID`).
Мастер восстанавливает их при старте, поэтому засыпание и перезапуск Render не стирают данные.
Потеря возможна только за последние ~2 минуты до сбоя. Настройка: см. RENDER_VARIABLES.md.

## Важно перед продакшеном
- Render Free усыпляет сервис и стирает диск. Данные восстанавливаются из Telegram-бэкапа; лучше включить бесплатный монитор (UptimeRobot) на `/health`, чтобы сервис не засыпал.
- Все дочерние магазины работают **на одном сервере** мастера. Много магазинов — нужен отдельный сервер или контейнер на каждый.
- Отчёты о продажах присылает сам дочерний процесс. Модифицированный магазин может занизить выручку. Полной защиты без внешней платёжной сверки здесь нет.
- Telegram Stars не переводятся между ботами автоматически. Комиссия оплачивается счётом мастера.
- Проверяй руками: создание бота (живой токен и MySQL), оплату комиссии, приостановку, сброс пароля. В этой сборке модуль проверен юнит-тестами с заглушками, без живых Telegram/MySQL/Render.

## V13: имя бота везде + WAIP STUDIO
- Имя магазина (`SHOP_TITLE`) теперь подставляется во все тексты бота, кнопки, меню, счета и WebApp (раньше часть строк была зашита как «WAIP SHOP»).
- **Сайт `/studio/`**: админ и модераторы создают ботов-автодонатов для клиентов. Поля: имя, цвет, MySQL host/login/пароль/база, логотип, токен бота, ID админа клиента.
- Клиент платит **250 ⭐** кнопкой в отдельном боте студии. Модератору записывается **60%**, **40%** остаются на балансе бота. Заказ админа — 100% на балансе бота.
- Ботам, созданным через студию, недельная комиссия 20% **не начисляется** (клиент уже заплатил 250 ⭐).
- Данные клиента шифруются (Fernet) и стираются из заказа после создания бота.
- **Ограничение Telegram:** бот не может сам переводить Stars на аккаунт пользователя. Доля модератора фиксируется в журнале, модератор мгновенно получает уведомление, админ отмечает «выплачено» после перевода.
- Тесты: `python -m unittest tests/test_studio.py -v`
